## What's Next: Phase 4 — Architecture

The UI prototype is solid. Phase 4 defines the backend that powers it.

### Six Topics to Work Through

1. **Data Model**
   - Rust structs for: Project, Session/Handoff, Document, Relationship
   - See `docs/design-brief.md` § Entities for requirements
   - Key question: how much derives from git metadata vs. user-configured?

2. **Storage Strategy**
   - Design brief left this deliberately open. Options: SQLite, filesystem-first, hybrid
   - SQLite proven in MIR (reference project). Filesystem-first is portable and git-trackable.
   - Hybrid (SQLite for index/search, files for user content) is likely the answer

3. **Tauri IPC Command Surface**
   - Define the exact `invoke()` commands the frontend needs
   - Look at `data/mock.js` exports — each one maps to at least one IPC command
   - Commands for: list projects, get project detail, list sessions, get session, search, etc.

4. **Rust Backend Modules**
   - Git operations (libgit2 or git CLI)
   - File watching (notify crate)
   - Full-text search (tantivy or similar)
   - Markdown parsing (pulldown-cmark or comrak)
   - Session/handoff import

5. **Claude Code Integration**
   - Design the handoff skill that writes structured files taurhaus can import
   - Explore whether Claude Code session IDs can be captured
   - File format for handoff documents (JSON? YAML? Markdown with frontmatter?)

6. **File Watching Architecture**
   - Auto-detect changes to project files and git state
   - Configurable ignore patterns (`.gitignore` baseline + taurhaus overrides)
   - Must handle large codebases without excessive resource usage
   - Balance between real-time updates and CPU/memory cost

### Key Design Documents to Read
