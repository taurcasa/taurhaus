## Session Notes

This session focused on solving Codex and Gemini active/idle detection, which had been unreliable. The previous approach used IO decay timers that were either too short (false idle during work) or too long (stale active after completion).

### Detection Strategy Per Tool (Final)

- **Claude**: IO hysteresis via `/proc/PID/io` rchar. Two consecutive above-threshold polls confirm activity. Unchanged, works reliably.
- **Gemini**: TCP socket detection via `/proc/PID/fd` + `/proc/PID/net/tcp`. Gemini closes all :443 connections when idle at prompt, giving instant detection in both directions. Also fixed Gemini session directory naming (newer versions use project dir name instead of SHA-256 hash).
- **Codex**: Session file mtime ONLY with `CODEX_ACTIVE_THRESHOLD = 10s`. TCP is unusable because Codex maintains HTTP keep-alive connections to Cloudflare/OpenAI :443 indefinitely after finishing work. Total active-to-idle latency is ~14s (10s threshold + 4s hysteresis). Brief false-idle flashes during long API thinking gaps are a known accepted limitation.

### Key Technical Findings

Extensive empirical monitoring (via `/tmp/monitor_sessions.sh` polling TCP connection counts every 2s) revealed:
- Gemini drops to 0 ESTABLISHED connections when idle (perfect for TCP detection)
- Codex keeps 1 ESTABLISHED connection (HTTP keep-alive) forever after work completes
- During active work, Codex fluctuates between 1-2 connections, making count-based detection unreliable
- Process dedup was keeping the fnm shim PID (lower) instead of the native binary PID (higher) that owns the API sockets; fixed by sorting by PID descending before dedup

### Other Fixes

- Git branch and dirty indicator now show on first launch by caching git status during the startup reseed and emitting a `projects-reseed-complete` event to refresh the frontend.

### Task Board Observation

Discovered that Codex creates `TODO.md` files (same format as Gemini), and our task scanner always attributes `TODO.md` to Gemini regardless of who wrote it. This is because the Gemini parser runs on every project unconditionally. Not fixed yet — needs a design decision on whether to make TODO.md attribution tool-aware or treat it as tool-agnostic.
