## Session Notes

This session focused on fixing macOS terminal emulator integration, specifically making session indicator clicks in the sidebar reliably open/focus iTerm2 with the correct tmux pane. The core challenge was macOS's click-to-activate behavior: clicking any part of the taurhaus window activates taurhaus first, and macOS's focus protection ignores activation requests for other apps during its ~250ms window-switch animation.

Five iterations of fixes were tested on the remote Mac Mini: (1) iTerm2's AppleScript `command` parameter is unreliable — switched to `write text`, (2) `FocusOnly` was a no-op when no terminal was running — changed to always use `EnsureOpen` on macOS, (3) double iTerm window on fresh launch — split launch logic by `is_running()` state, (4) blocking `.output()` caused focus steal when WebView reclaimed focus — switched to non-blocking `.spawn()`, (5) fixed delays (100ms, 350ms) were race conditions against macOS window manager animation.

The final solution is event-driven: an AppleScript polls System Events until taurhaus IS frontmost (confirming the click-activation settled), then immediately activates the terminal. This is reliable regardless of animation speed or system load. User confirmed "that's the version we've been looking for — snappy and feels right."

Session also confirmed that activity detection works on macOS for all three tools (Claude, Codex, Gemini) via the platform abstraction layer (darwin.rs). Codex was manually tested and working. Build artifacts (DMG + daemon binary) were saved locally to `builds/macos-aarch64/` and a full provisioning guide was written to `docs/macos-provision.md` to enable recreating the Mac Mini environment from scratch.
