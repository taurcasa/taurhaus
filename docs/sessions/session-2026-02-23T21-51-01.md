## Session Notes

This session focused on three areas: sidebar polish, navigation bug fixes, and per-project position memory.

**Sidebar visual hierarchy** (commit `1ea1b05`): Brightened project name text (white/60 to white/75), thickened active item left border (2px to 3px), added branch name pills with rounded backgrounds, and iterated through three approaches for group separation (colored vertical bar, horizontal divider, whitespace-only) before settling on pt-8 spacing with no rule — validated through Gemini 3.1 Pro consultation.

**Navigation bug fixes** (commit `ac7785f`): Fixed file tree collapsing when navigating from Git diff to Files tab (parent directories weren't being auto-expanded in `openFile`). Fixed layout overflow where the Files tab inner container lacked `min-w-0`, allowing flex items to push content past window bounds. Changed mouse back/forward handling from `mouseup` to `mousedown` to intercept before WebView2 acts.

**Per-project position memory** (commit `b0dfa46`): Implemented a `$bindable` position pattern where each tab component (GitTab, TaskBoard) exposes its view state via a `position = $bindable(null)` prop. Shell saves these opaque snapshots per project in a Map and restores them on return. Key design decision: outward sync uses `$bindable`, but restore uses separate props (`gitNavTarget`, `restoreTarget`) to avoid a race condition where the outward sync effect overwrites the restore signal on mount. This pattern was chosen over lifting state into Shell for better extendability — new tabs only need to add the `$bindable` position prop and handle their own restore logic. The initial overview landing is also now correctly pushed to nav history.
