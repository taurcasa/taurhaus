# Quiet information and one lead notice per source event

## Result

**[I — proposed contract, not shipped]** Accept information without creating an obligation to act, continue, acknowledge, or generate a turn. Normalize that expectation once, before choosing a delivery path. Keep the information available for the next read earned by real work. Render each logical lead notice once with its permitted source references; a workflow echo or task-metadata observation enriches that notice rather than generating another one. Assignments, valid GO releases, actionable corrections, review requests, interventions and stops retain their action path. This proposal changes neither lifecycle authority nor the five-line assignment contract. Basis: `T:docs/team-delivery-standard.md:19`, `:27`, `:31`; `T:docs/design/info-only-and-notice-dedup-brief.md:13`; source inventory below.

**[S — principal finding]** There is already a partial structured contract: INFO-prefixed sends acquire an orchestration block and workflow `kind=info`, `action_required=false`, `no_response_needed=true`. The daemon's general inbox gate instead examines assignment-message identity, `priority=low`, and empty text. It does not consult that contract. Moreover, a cron writer can append a low-priority notice and separately inject it through tmux. Merely improving role wording or setting the existing low priority is therefore insufficient across all paths. Evidence: `M:src/main.rs:562`, `:689`, `:960`; `M:src/daemon.rs:1523`, `:1654`, `:1875`, `:1898`; actual C06–C09 below.

**[I — scope and confidence]** High confidence in the source-level mismatch and M1 identity reuse; medium confidence in this bounded implementation design pending review and conformance tests. No harness wake behavior, monetary saving, M1–M3 gate, or design approval was verified in this lane. “One notice” is a projection and logical-delivery invariant, not an exactly-once model-exposure guarantee across crashes or foreign native writers. Basis: `T:docs/design/mesh-messaging-overhaul-research.md:155`, `:157`; `C:docs/operations/telemetry-contracts.md:63`.

## Recommendation

### 1. Accepted response expectation and wake policy

**[I — schema]** Add optional semantic `response_expectation: action | info` to the accepted message contract. Its inbox serialization should follow the existing camelCase convention as `responseExpectation`; workflow/monitor adapters may retain their current snake_case fields and expose the same semantic value. Preserve original body bytes/provenance and existing `action_required` / `no_response_needed` compatibility meanings. Add expectation provenance (`explicit`, `prefix`, `legacy_intent`, `generated`, `legacy_default`) and a policy revision in observation metadata, not role prose. Priority orders eligible actions; it does not decide whether an action obligation exists. Basis: `M:src/types.rs:12`, `:31`; `M:src/main.rs:562`; overhaul `T:docs/design/mesh-messaging-overhaul-research.md:96`.

**[I — authoring precedence]** Offer the proposed expectation flag tested as unavailable in C20. It is optional when the leading prefix is present; both structured API callers and humans can be precise without duplicating the five-line contract. Explicit expectation wins over inference **only where there is no contrary explicit declaration**: an action prefix with explicit info, an info prefix with explicit action, or incompatible structured action intent is rejected before acceptance. Report the conflict to the sender; do not silently accept an apparently actionable body as quiet. A generated assignment/GO/stop class cannot be downgraded by a generic flag. Basis: current lint/intent seam `M:src/main.rs:689`, `:574`; archive mislabeling above.

| I: accepted or legacy case | Required decision |
|---|---|
| Explicit info or leading INFO; no conflicting action declaration | `info`, no wake; preserve availability. Urgent+info does not trigger a turn. |
| Explicit action or ACTION REQUIRED; no conflict | `action`, eligible wake. Reject an explicit low-priority action combination at new acceptance with a useful conflict error, rather than retaining today's accidental suppression. |
| Generated assignment, valid GO, stop, action-required correction | `action`; event class and current authority win. Wake eligibility does not authorize execution before GO or past a stale assignment. |
| Legacy `action_required=true` plus `no_response_needed=true` | `action`; no acknowledgment duty. Nudges and completions prove why this combination is valid (`M:src/idle_monitor.rs:1008`; scratch workflow line 17). |
| Legacy recognized info intent with no action evidence | Interpret as info through one compatibility normalizer; retain original fields. |
| Legacy low priority with no usable expectation | Preserve deferred wake behavior but label expectation unknown/legacy. Low priority alone is not evidence that the sender requested no work. |
| Legacy unprefixed default message / unknown enum | Preserve prior actionable/default delivery behavior; expose unknown expectation. Never quiet potentially important traffic by guessing. |
| Conflicting foreign/legacy declarations | Preserve the record and surface one action-eligible conflict notice; do not resolve by timestamp or a body model. Foreign text cannot change lifecycle authority. |
| Empty legacy body / empty delta | No wake and no model-visible continuation. New ordinary empty messages are rejected; structured action events first render their valid operative card, so GO is not mistaken for an empty-body check. |

**[I — decision ownership]** One pure normalization/wake predicate must be used before native mailbox publication, daemon wake batching, cron direct delivery, terminal action-key selection, and future hook/push presentation. Add per-message decisions even for mixed batches; one action wake must not drag an unrelated INFO backlog into a new notification. Keep current assignment/effort and runtime-identity validation outside this predicate. Basis: `M:src/daemon.rs:1523`, `:1654`, `:999`, `:1898`; `T:src-tauri/src/coordination/orchestrator/delivery.rs:111`.

### 2. An INFO notice must stay outside an automatic wake surface

**[I — necessary staging decision]** For feature-enabled teams, put newly accepted info in a **deferred inbox array**, proposed at `state/deferred-info/<member>.json`, using the existing locked array primitive and recipient access rules. Do not put it into the harness-polled `inboxes/<member>.json`, emit a channel event, inject terminal text, or block Stop for it. Both existing inbox and deferred info participate in the sanctioned earned read. This is a small retained queue with the current format, not a message journal, replacement transport, scheduler, native adapter, or automatic task subscription. Use the same choice for all four harnesses to avoid moving pending bodies during a harness switch. The necessity comes from native mailbox behavior being outside the daemon filter: `T:src-tauri/src/coordination/orchestrator/delivery.rs:115`; corpus `T:docs/design/mesh-messaging-overhaul-research.md:59`. The location and implementation are **UNVERIFIED proposal**, gated below.

**[I — queue/read contract]** Accept once into exactly one selected array with a message ID; do not append to both then delete one. Return durable acceptance separately from workflow-echo coverage. Explicit reads merge eligible inbox messages and deferred info, apply audience checks first, bound output and expose overflow without advancing past unseen entries. Mark only returned IDs at their original physical source; reading or offering an item does not manufacture an acknowledgment or lifecycle uptake. Never move deferred info into the native mailbox merely to drain it. Retry partial mark failures by identity, retain uncertainty, and use one per-recipient lock for duplicate suppression at the read/offer seam. This extends existing array/read behavior at `M:src/inbox.rs:106`, `M:src/main.rs:1191`, `:1221`; no cross-file atomicity is claimed.

**[I — limits]** Unknown/incompatible clients may not enable deferred delivery. No silent downgrade that hides info from their reads. Before a downgrade, perform an explicit quiescent drain/export with a pending count; never flush info into a native mailbox in the background. Existing inbox history is left where it is, so already published native info cannot be retroactively guaranteed silent. Foreign native writers remain outside this guarantee and are disclosed as uncovered. Basis: `M:src/types.rs:13` (no flatten map for inbox extensions), `M:src/inbox.rs:109` (typed rewrite); compatibility section below.

### 3. During work, idle, Stop and compaction

**[I — busy]** On info arrival, persist and record a deferred decision, then leave the active turn alone. Do not paste text, steer the turn, interrupt a tool, force an extra tool read, or announce the backlog to the model. Fold bounded information into the next read that the seat was already making for its work or an explicit user request. If no earned read happens, the information remains pending indefinitely within declared retention, without starvation timers that convert it into an action. Source basis: overhaul `T:docs/design/mesh-messaging-overhaul-research.md:161`; brief `:92`; current native bypass in the inventory.

**[I — idle/Stop]** The same queue stays quiet while idle. An empty machine delta is a normal no-op: return the harness's empty successful hook response, no additional context, no stop-block reason, no app-server call, and no terminal write. An info-only delta also does not continue Stop. An action arriving after Stop uses the existing idle wake route; do not wait for a hook that cannot run in an already idle seat. A model-chosen explicit read can still incur tool/input/output overhead; “free” means no additional model invocation caused by the machine check, not zero filesystem work or zero billable bytes in an earned turn. Basis: C10, C19; `M:src/main.rs:1208`; overhaul `:60`, `:194`.

**[I — corrections, GO and stop]** A correction to current instructions must be authored as action and identify what it supersedes; a new valid GO uses assignment-bound lifecycle authority. Keep these eligible during busy or idle periods through the current permitted action boundary, preserving pane/session guards and user-input handling. A stop is control-plane work and bypasses an INFO backlog; it need not buy a model turn merely to acknowledge stopping. None of these exceptions permits prose GO to clear a wait. Source basis: delivery standard `T:docs/team-delivery-standard.md:27`, `:53`; Mesh wait `M:src/idle_monitor.rs:700`; terminal selection `M:src/daemon.rs:999`.

**[I — compaction]** Leave the single compaction owner and its idempotency record unchanged. A compacted seat receives necessary resumable task context through the established HookStdout or MeshInbox route; that is recovery, not a quiet-info violation. Do not add arbitrary deferred info to this mid-work reinjection. Logical notice IDs survive context changes; a separately recorded recovery offer can intentionally reintroduce necessary context without pretending it is a new source event. Basis: `T:src-tauri/src/coordination/compact_hook.rs:575`, `:596`, `:626`, `:649`; overhaul `:184`.

### 4. One source identity, several physical observations

**[I — canonical key]** Normalize observations into `Notice { event_key, delivery_key, expectation, operative_refs, sources[] }`. The event key is **(source authority, team incarnation, originating event identity)**; the delivery key adds the logical recipient and notification purpose. Root path is physical provenance, not team incarnation. For legacy archives lacking a stable incarnation, use a captured config/creation identity and archive namespace only within that source cut; do not claim continuity across recreation or root moves without an authoritative mapping. This instantiates the overhaul identity fields (`T:docs/design/mesh-messaging-overhaul-research.md:89`, `:95`, `:98`, `:101`) without creating a journal.

**[I — exact M1 reuse]** For a monitor observation, use M1's `message:<nonempty message_id>` identity component **unchanged**, scoped to the same team and task as M1. Inbox `id` is the message-side alias. The `message_sent.eventId` identifies the physical echo, not a second logical notice. For leadless health, retain M1's seat plus ordered ignored-nudge-ID fallback **only for metadata launch_health without a message ID**. Do not generate a lead delivery for a leadless record. Preserve separate counts for the two nudges and subsequent health episode, attributed to the affected seat. Source: `C:src-tauri/src/coordination/routing_report/mesh.rs:20`, `:33–65`, `:98–117`; `C:docs/operations/telemetry-contracts.md:39`.

**[I — other identities]** For an authored message use its source-scoped message ID. For newly generated lifecycle notices, pass the committed source event ID into the existing notice writer instead of allocating an unrelated logical cause. A ruling uses authority+task+ruling sequence, and an assignment notice includes assignment generation plus phase (`assigned`, `released`, or correction event). A task ID, owner, status, timestamp, summary or body hash alone is never a dedup key. Repeated progress updates and recurring monitor episodes remain distinct. Historical lifecycle/message pairs without an explicit link stay separate or marked possible-related; do not retroactively mint a causal join. Source basis: scratch identity witness; `M:src/main.rs:636`, `:3909`; overhaul `:188`.

**[I — provenance and precedence]** Each source retains source kind, actual root/path, archive/file generation, line/byte offset or array index, physical event/message ID, source timestamp, first-observed time, claimed author and verification class. Canonical lead alias resolution only determines the recipient; it never overwrites the path. Task/monitor authority supplies the authoritative event fields; an authorized inbox supplies the body. M1's metadata-first choice remains unchanged for metric values, but the notice projector retains all source refs instead of dropping the losing observation. Conflicting task/seat/kind under one claimed identity is an integrity error, not a reason to hide an action; render one conflict with both restricted-as-needed references. Source: `M:src/config.rs:138`; `C:src-tauri/src/coordination/routing_report/mesh.rs:105`; overhaul `:132`.

**[I — rendering and exposure]** Apply audience/independent-review permissions **before** grouping or listing sources. Lead view renders one bounded body/operative reference plus source badges, e.g. “Launch health: worker; sources: inbox, workflow, task metadata.” A newly discovered echo updates provenance silently and cannot wake or advance a model-read receipt. The current recipient daemon/read path uses the same logical delivery identity; workflow and metadata readers are observers, not new notice producers. Rebuilding the lead view does not send messages. An explicitly new correction/GO/ruling sequence is a new event and remains eligible. Source basis: overhaul `:96`, `:128`, `:186`, `:192`; brief `T:docs/design/info-only-and-notice-dedup-brief.md:96`.

**[I — boundary of “once”]** A reader can enforce one row per key and an existing writer can idempotently suppress known repeat intents under its lock. That is not an atomic lifecycle+notice transaction or exactly-once exposure after a crash. Record unknown outcomes and reconcile the same notification identity; never replay the task transition merely to resend its notice. Foreign imports remain source-scoped and do not become authenticated local events because IDs or text match. No raw-array cleanup is required to obtain a deduplicated view. Basis: `M:src/main.rs:4163`; overhaul `:155`, `:188`, `:190`.
