## Working agreements in force (kickoff, broadcast 2026-09-07)

- Every implementation lane in its own worktree named in the assignment
  (`/tmp/<seat>-w2-<task>`, branch `<seat>/w2-<task>`); code lanes never edit the
  main checkout. Docs seats commit from the main checkout by pathspec only after a
  separately-run `git status --porcelain`.
- Per-seat `CARGO_TARGET_DIR=/tmp/<seat>-cargo-target`; count builds by process name,
  `pgrep -c 'cargo|rustc|clippy-driver|rustdoc'` (corrected 2026-09-07: the `-f` form
  counted waiting shells and the gate command itself; judge-astra's observation), and
  wait while two or more run; stagger at three.
- Gate: `bun run check:task` on an isolated worktree of the exact commit; RESULT names
  the commit. Landing on `master` is serialized by the lead after the exact gate.
- Captures only from your own display, geometry and PID asserted, isolated
  `XDG_DATA_HOME`, WSL2 env vars per CLAUDE.md.
- Budgets: gross changed lines (additions + deletions) in production paths per
  `git diff --numstat <base>..HEAD`, tests and fixtures excluded, method fixed per lane.
  A raise is recorded before the excess (`budget_raised` ruling); an unapproved
  oversize diff fails review with an `oversize_diff` ruling.
  Clarified 2026-09-07 (#30): the count is task-owned lines against the lane's fixed
  baseline (plus any named prerequisite commit the lane stacks on); upstream landings by
  other lanes never enter a lane's count. Reviewed tips land by merge and the lead gates
  the merge; a rebase is required only for a real conflict, so a moving master creates
  no budget pressure.
- Start-on-GO lanes carry `--awaiting-go`; released with `mesh task update <id> --go`.
- Restart cursor at every long wait: cwd, code tip, rubric tip, tool hash, active
  root, pending rulings, next action.
- Regression rule (wave-1 closure finding 10): a regression test earns its keep when
  it fails against the old code. Evidence-summary rule (finding 11): totals and
  per-root figures including zeros.

**Proportionality rule (operator, 2026-09-08; lead applies):** a correction round is spent only when a finding changes what the user sees or does, or when a hard-rule claim (privacy, credentials) is otherwise unproven. A finding that only strengthens an instrument, tightens a test or restates a known limitation becomes a register row with a lane, not a new commit + gate + confirm cycle; one-word copy fixes ride the next lane that touches the file when design acceptance allows. Hero surfaces keep two independent reviews (kickoff), one round each, diff-confirms for deltas. The ledger names any loop stopped on this rule.
