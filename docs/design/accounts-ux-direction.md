# Accounts UX — chosen direction (pending operator approval)

Synthesis of the design panel over [`accounts-ux-overhaul.md`](accounts-ux-overhaul.md): three committed concepts — **Hub** (a first-class Accounts place), **Ambient** (launch-moment strips + titlebar usage pulse, popover home), **Object** (account chips with usage rings threaded onto everything) — judged by an operator-fit lens (C2 44 · C1 42 · C3 38) and a coherence-and-cost lens (C1 35.5 · C3 31.5 · C2 29).

## Arbitration

**The Hub structure wins, carrying the Ambient concept's one decisive element in a calm form.** The split resolves on margins and on what each win was made of: Ambient's two-point operator-fit edge came almost entirely from its always-visible usage signal; the Hub's six-and-a-half-point coherence edge is structural — the home matches the one existing house pattern for an app-global place (the Settings main-panel takeover), consumes every existing component instead of re-skinning them (`UsageMeter` verbatim, `SlideOver`, `ContextMenu`, `accountMenu.js` rows), and was the only concept honest about the daemon/protocol cost hiding inside per-member accounts. A popover as the *home* fails FR1 at density, and a 20px strip under every launch cluster taxes exactly the dense surfaces this app protects. So: Hub skeleton, Ambient's heartbeat.

## The direction

1. **Accounts home** = a Settings-style main-panel takeover (sidebar and titlebar stay put). One section per registered tool, rows not cards: health dot · identity + config dir · relationship summary (`2 pins · 1 team`) · full `UsageMeter` bars always visible · disclosure. Expanded rows manage the relationships: pins as removable chips, teams listed with links, `Set as global default`, `Sign in…` (recovery for a signed-out row), `Reveal directory`. Unhealthy rows auto-expand on open; a freshness timestamp + refresh sit in the header; detection-degraded is a first-class banner.
2. **Ambient usage signal** (the graft, replacing Ambient's titlebar pulse): the sidebar-footer Accounts button — beside the settings gear — carries a compact worst-relevant-window readout (magnitude, not just a dot; amber before a launch would fail, red on signed-out/unauthorized), and **hover opens a compact usage board** (the home's meter column rendered as a `ContextMenu`-clamped popover) for zero-navigation headroom checks. Click opens the home. No titlebar additions.
3. **One shared picker** extracted from `AccountChooser` (which becomes a thin wrapper, behavior contract and tests preserved), used at every start/resume surface, with the Object concept's **scope-aware remember label** (`this launch · this project · this member · this team`) and, for team scope, its consequence line: *"the whole team moves to this account's root; conversation history does not follow."* Picker austerity is a rule: rows + usage + one `Manage accounts →` footer (which also carries the add-account door — the mid-exhaustion moment must not be a two-hop detour); management actions never creep in.
4. **Managed teams**: per-member picker on Codex/Grok roster rows beside `ModelSelect`; the Claude roster uses the same slot for a per-team picker backed by the daemon root registry. Mesh nodes gain a positive account line (label + micro-meter) that *replaces* the opaque-wrapper note via the existing meshLayout growth rule; the fallback state uses the Object concept's wording: *"was account2 → now personal"*, with a paused, reasoned picker on resume.
5. **FR5b — the switch journey** (post-panel addition, rides this structure): exhaustion on a team surfaces the same interrupt contract as everywhere else, proposing *Switch team to…*; the flow is stop → migrate/re-point → resume with the switch onboarding (old account named, transcript location pointer, task-ledger rebuild instruction). The hub's team rows and the resume path both offer it deliberately, not only at failure.
6. **FR7 mechanics**: the hub's alias strip explains what a base-carried selector does and offers the Object concept's one-click **Convert to pins** (writes project pins for the affected projects, leaves the alias untouched); the HoverCard gains a one-line account readout per session.
7. **Implementation requirements adopted from the panel**: preview results cached per (project, tool, accounts-generation) and re-resolved on visibility; usage meters render an `observed_at`-age "last known" dashed state (stale-but-confident meters are their own failure mode); one tested render-rule function decides ambient-signal visibility so calm is enforceable; `Member.account_id` is priced as a daemon-side protocol slice, not a frontend field.

## What this costs (headline honesty)

New: the home surface, the sidebar-footer entry + board popover, the extracted picker core, add-account flow (SlideOver + managed login terminal), reverse-index IPC (account → pins/teams), global-default setter, registry login-command fields, mesh-node account line. Backend: per-member account field through the daemon pipelines (protocol bump), the per-team Claude root authority + FR5b switch operation (the largest slice), golden churn priced in. Sequenced after approval as backend lanes + design-led frontend lanes with the visual dual review.

## Approval

The operator approves or amends this direction before any implementation lane launches. Full concepts and both verdicts are preserved in the session scratchpad; this document is the binding summary.
