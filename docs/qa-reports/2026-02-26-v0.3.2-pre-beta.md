## 4. Security Audits

### 4.1 Rust Dependencies (`cargo audit`)

**Result: CLEAN** — 0 advisories across 596 crate dependencies.

3 known advisories are suppressed in `.cargo/audit.toml` with documented rationale (lru unmaintained, git2/libgit2 advisory, GTK3/glib on Linux only). See `docs/known-advisories.md`.

### 4.2 npm Dependencies (`npm audit`)

**Result: 4 vulnerabilities** — all fixable via `npm audit fix`.

| Package | Severity | Impact on taurhaus |
|---------|----------|--------------------|
| svelte <=5.51.4 | moderate | SSR-only XSS issues. **N/A** — Tauri does not use SSR. |
| rollup 4.0-4.58 | high | Build-tool path traversal. **N/A** — does not affect shipped binary. |
| devalue <=5.6.2 | low | Prototype pollution in eval. **N/A** — we don't eval devalue output. |
| basic-ftp <5.2.0 | critical | Path traversal in downloadToDir. **N/A** — transitive dev dependency, not shipped. |

**Assessment**: None affect the shipped application. All are SSR-specific, build-tool-only, or transitive dev dependencies. Running `npm audit fix` will clear them for hygiene.

## 5. Coverage Gaps

### 5.1 Untested Frontend Modules

| Module | Lines | Risk | Notes |
|--------|-------|------|-------|
| taskHelpers.js | ~20 | Low | Pure functions (badge classes, labels). Quick win. |
| toolLogos.js | ~45 | Low | SVG data + tool name mapping. Quick win. |
| logger.js | ~32 | Low | Log forwarding to Rust. Quick win. |

All 17 Svelte components have their logic tested via extracted `.js` modules. Component rendering (layout, CSS) is covered by E2E tests.

### 5.2 Untested Rust Command Handlers

These 9 files in `src-tauri/src/commands/` have **no unit tests**. They sit between the frontend IPC layer and the well-tested query/logic modules:

| File | Functions | Risk |
|------|-----------|------|
| files.rs | File tree, file read | Medium — path traversal validation |
| git.rs | Git status, commits, diff | Low — delegates to tested git module |
| sessions.rs | Session list, launch | Medium — argument handling |
| settings.rs | Settings get/save | Low — thin wrapper around tested queries |
| relationships.rs | Relationship CRUD | Low — thin wrapper |
| search.rs | Search query | Low — delegates to tested indexer |
| daemon.rs | Daemon lifecycle | Medium — error mapping |
| logging.rs | Log receiver | Low — fire-and-forget |
| errors.rs | Error types | Low — type definitions |

**Mitigating factor**: The E2E tests exercise these handlers end-to-end for all happy paths. The gap is in error paths and edge-case input validation.

### 5.3 Missing E2E Scenarios

| Scenario | Risk | Notes |
|----------|------|-------|
| Add Project modal | Medium | First thing a new user interacts with |
| Dark/light theme toggle | Low | Visual only, no logic risk |
| Daemon disconnect/reconnect | Medium | Recovery behavior untested |
| Terminal launch (tmux) | Low | Requires running tmux server |
| Error states (DB lock, timeout) | Low | Hard to trigger reliably in E2E |

## 7. Recommendations

### Before closed beta (priority order)

1. **Run `npm audit fix`** — clears cosmetic vulnerability reports (~5 min)
2. **Add unit tests for 3 small utility modules** — taskHelpers, toolLogos, logger (~1 hour, +~15 tests)
3. **Add basic tests for top command handlers** — files.rs, sessions.rs, daemon.rs (~2-3 hours, +~30 Rust tests)
4. **Manual smoke test on Windows** — verify installer, first-run wizard, daemon bootstrap chain

### Post-beta improvements

5. Add E2E test for Add Project modal workflow
6. Add error-path testing for daemon disconnect/reconnect
7. Accessibility audit (axe-core in E2E)
8. Performance benchmarks (app startup time, tab switch latency)
